Part 0 — Fix APT (the signing-key problem)

Symptoms on an old image:

sudo apt update → NO_PUBKEY ED65462EC8D5E4C5
sudo apt install ... → 404 Not Found on the package files

Why: In 2025 Kali lost its old repo signing key (ED444FF07D8D0BF6) and issued a new one (ED65462EC8D5E4C5). An image built before ~May 2025 can't verify the current release file, so apt refuses to refresh the index and keeps using the stale one — whose package versions have since been purged from the mirror pool, which is why the install 404s.

Fix (official Kali remedy):

sudo wget https://archive.kali.org/archive-keyring.gpg -O /usr/share/keyrings/kali-archive-keyring.gpg
sha1sum /usr/share/keyrings/kali-archive-keyring.gpg

The checksum should be exactly:

603374c107a90a69d983dbcb4d31e0d6eedfc325

Then refresh:

sudo apt update

It should now complete with no NO_PUBKEY line.

Do NOT run apt full-upgrade / apt upgrade. On an old image that's a multi‑GB, long‑running operation that can leave the VM broken (kernel/driver mismatches). You only need cmake.

Part 1 — Install the build toolchain

make and g++ ship with Kali; only cmake is missing.

sudo apt install cmake
cmake --version
part 2 — Build bkcrack (replaces pkcrack)

The original guide runs git clone https://github.com/keyunluo/pkcrack, which now prompts for a GitHub login — GitHub's behaviour when a repo is private or deleted. Rather than hunt for a mirror of an abandoned fork, use bkcrack, which performs the same ZipCrypto known‑plaintext attack and is actively maintained.

cd ~
git clone https://github.com/kimci86/bkcrack
mkdir bkcrack/build
cd bkcrack/build
cmake ..
make
find ~/bkcrack -type f -name bkcrack

The binary lands at ~/bkcrack/build/src/cli/bkcrack.

If your cmake is 4.x and it errors with "Compatibility with CMake < 3.5 has been removed", re-run the configure step as cmake -DCMAKE_POLICY_VERSION_MINIMUM=3.5 ... (Not needed for current bkcrack, but handy to know.)

Stage the binary next to wherever your evidence will live, e.g.:

cp ~/bkcrack/build/src/cli/bkcrack ~/Downloads/
Part 3 — Bring the evidence to Kali

Make sure SSH is running on Kali so a transfer can connect:

sudo systemctl start ssh
systemctl is-active ssh

From Workstation-Desk, copy both E:\Ione\exfiltratroll.zip and the loose E:\Ione\astral.jpg to Kali. Either tool works:

Part 4 — Inspect the archive (don't skip this)
./bkcrack -L exfiltratroll.zip

Confirm before attacking:

Encryption = ZipCrypto — this is what the known‑plaintext attack beats. If it said AES, this attack cannot work.
Compression = Deflate — note this; it dictates how we prepare the plaintext.
All four files are present: 2EWX83.txt, astral.jpg, fog.jpg, prince.jpg.
Part 5 — The known-plaintext attack

Why it works: Legacy ZipCrypto encryption is broken against known plaintext. Because astral.jpg exists both inside the encrypted archive and as a loose file, we have a complete known plaintext. bkcrack recovers the three internal keys, and those keys unlock every file in the archive — not just astral.jpg.

astral.jpg is stored Deflated inside the archive, so bkcrack needs the compressed form of our plaintext. Zip it with the same Deflate method:

7z a plain.zip astral.jpg

(Optional) sanity-check the compression is close:

./bkcrack -L plain.zip

An exact packed-size match isn't required — bkcrack only needs a short run of matching compressed bytes — but closer is better.

Run the attack:

./bkcrack -C exfiltratroll.zip -c astral.jpg -P plain.zip -p astral.jpg

Success ends with:

Keys: <k0> <k1> <k2>
Part 6 — Unlock and extract

Rebuild the archive with a password you choose, using the recovered keys:

./bkcrack -C exfiltratroll.zip -k <k0> <k1> <k2> -U unlocked.zip cracked

Extract into a clean subfolder (no space after -p or -o):

7z x unlocked.zip -pcracked -orevealed

Everything is Ok means every file passed its CRC check — i.e., correct decryption. A wrong key would fail here instead, so this step is self-verifying. Confirm the file types:

file revealed/*

You should see three JPEG images and one ASCII text file.

Part 7 — Return the files to C:\ (the final gotcha)

Transfer the four files from Kali back to Workstation-Desk.

They must land in the ROOT of C:\ — C:\2EWX83.txt, C:\astral.jpg, C:\fog.jpg, C:\prince.jpg. Not in a subfolder. If you drag the revealed folder across, the files end up at C:\revealed\..., one level too deep, and the checks stay red. Move them up to the drive root and give the checks up to a minute to re-poll.

When all four files sit at the root of C:\, the four objectives flip to Desired State.

What the original guide got wrong (summary)
Expired APT signing key — add the keyring fix in Part 0; never full-upgrade.
keyunluo/pkcrack repo is gone — use bkcrack instead (Part 2).
KnownFile.zip vs KnowFile.zip typo in the original pkcrack command — avoided here by bkcrack's clearer syntax; general lesson: keep filenames consistent.
Final file location — the checks read the root of C:\, not a subfolder.
